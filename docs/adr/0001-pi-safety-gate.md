# Keep the Pi safety gate local and best-effort

To support task-scoped local work, this repository owns a best-effort Pi safety gate instead of adopting a third-party gate package. Agent policy still requires writes to stay in the assigned task worktree and requires explicit user authorization for direct integration, remote or authenticated access, publishing, and destructive actions with uncertain or persistent impact. The gate's heuristics may allow writes in any linked worktree, plain relative recursive deletes, and `wt merge` without prompting; those exceptions do not grant permission. Pi’s native confirmation stays authoritative when the gate requests confirmation; TUIOS and Herdr observe gate state without becoming approval channels. The gate is not an operating-system security boundary, and its policy continues to apply if either observer integration is unavailable.
